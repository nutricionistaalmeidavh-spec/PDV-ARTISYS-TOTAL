# E48–E54 Final Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Concluir E48–E54 no mesmo ArtiSys PDV local-first, mantendo venda/estoque/caixa/impressão canônicos, pagamentos manuais e produto comercial somente NÃO FISCAL.

**Architecture:** Novos verticais entram como serviços isolados sob `js/domains/*`, guardados pelo `ModuleService`, persistidos por migration incremental v8 e expostos pela API `/api/v1/vertical`. Autoatendimento reutiliza credenciais móveis locais e `/mobile`. E54 amplia o runtime de hardware existente e registra evidência de compatibilidade sem declarar hardware físico como homologado sem teste.

**Tech Stack:** Node.js 22, `node:sqlite`, Electron, HTTP LAN local, Node test runner, módulos locais `@artisys/printing` e `@artisys/serialport`.

**Spec:** `docs/superpowers/specs/2026-09-10-e40-e54-modular-verticals-design.md`

## Global Constraints

- Local-first; internet não é necessária para operação diária.
- SQLite só é aberto pelo servidor autoritativo.
- `SaleService` é o único motor canônico de venda.
- Pagamentos são registrados manualmente; sem TEF, gateway, API bancária ou confirmação automática de PIX.
- Superfícies comerciais novas são somente **NÃO FISCAL**.
- Nenhuma remoção destrutiva de schema legado.
- Módulos desativados bloqueiam mutações específicas no backend e escondem UI.
- E54 usa `BLOCKED_EXTERNAL` para equipamentos físicos não testados.
