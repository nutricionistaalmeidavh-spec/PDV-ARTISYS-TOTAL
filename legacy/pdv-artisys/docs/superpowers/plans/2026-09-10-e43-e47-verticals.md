# E43–E47 Vertical Modules Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implementar Pizzaria, Restaurante avançado, Delivery, Fast-food/Lanchonete e Mercado/Conveniência/Padaria como módulos opcionais sobre o mesmo núcleo do PDV.

**Architecture:** Cada vertical recebe serviço próprio e schema aditivo, mas reutiliza catálogo E40, módulos E42, `SaleService`, restaurante/KDS, estoque e impressão não fiscal. Gating é validado no backend e refletido na UI; nenhum módulo cria um segundo motor de venda, caixa ou estoque.

**Tech Stack:** Node.js 22+, CommonJS, SQLite local, Electron, interface mobile local existente, `node:test`.

**Spec:** `docs/superpowers/specs/2026-09-10-e40-e54-modular-verticals-design.md`

## Global Constraints

- Local-first/LAN; sem SaaS, CDN ou internet obrigatória.
- SQLite acessado somente pelo servidor local autoritativo.
- `SaleService` continua canônico para toda venda concluída.
- Pagamentos são somente registros manuais.
- Todo comprovante comercial é **NÃO FISCAL**.
- Sem NFC-e/NF-e/SAT/MFE/SEFAZ/certificado/provedor fiscal nos novos fluxos.
- Módulos podem ser ligados/desligados sem reinstalar e sem apagar histórico.
- Mutação específica de módulo desativado deve ser bloqueada no backend.
