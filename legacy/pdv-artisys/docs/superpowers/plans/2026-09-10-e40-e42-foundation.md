# E40–E42 Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implementar catálogo avançado, ficha técnica/insumos e o motor de módulos opcionais sem duplicar venda, estoque ou configuração.

**Architecture:** Novas capacidades ficam em serviços focados (`catalog-customization`, `recipes`, `modules`) e são persistidas por migrations incrementais. `SaleService`, inventory ledger, settings, EventBus/outbox e API local continuam canônicos; os novos serviços apenas enriquecem item/preço/consumo e fazem gating de capabilities.

**Tech Stack:** Node.js 22+, CommonJS, SQLite local, Electron renderer, `node:test`, servidor HTTP local existente.

**Spec:** `docs/superpowers/specs/2026-09-10-e40-e54-modular-verticals-design.md`

## Global Constraints

- Local-first; internet não pode ser requisito operacional.
- SQLite só é acessado pelo servidor local autoritativo.
- `SaleService` continua sendo o único motor canônico de conclusão de vendas.
- Estoque continua pelo ledger existente; novas baixas devem ser idempotentes.
- Pagamentos continuam apenas manuais.
- Fluxos comerciais e impressões permanecem somente **NÃO FISCAL**.
- Nenhuma remoção destrutiva de dados/schema legado.
- Módulos são configuração funcional local, sem paywall/licença online.
